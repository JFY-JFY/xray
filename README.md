# X-RAY 模拟投资大富翁游戏🎮

> 看得懂的公司，才值得你下注
>
> HACKATHON DEMO · 2026

一款运行在浏览器里的 **3D 金融投资博弈游戏**。你是这座金融城的**首席投资官**，掷骰巡城，遇到公司先看它的资料，再决定要不要掏钱。游戏的真意不在于掷骰运气，而在于训练一套判断公司真伪的方法——**照毛利率、验现金流、查增长、挑红黄绿、判结论**。

**每做完一次金融选择，游戏都会把这一题的「正确解法」和你代入公司数据后的推理过程摊开给你看，并指明它对应《防骗手册》的哪一条。**

## 快速开始

```bash
# 方式一：直接双击（完全离线，零依赖）
xray.html

# 方式二：起个本地服务（推荐，避免个别浏览器的 file:// 限制）
python -m http.server 8080
# 然后浏览器打开 http://localhost:8080/xray.html
```

- **零依赖、零构建**：three.js 已内联进单文件，全程**不发起任何网络请求**，不需要 npm / 打包 / 服务器。
- 建议使用 Chrome / Edge 等支持 WebGL 的现代浏览器，并**开启硬件加速**。
- 单文件约 **913 KB**（约 10,000 行），首次打开需解析内联 3D 引擎，低配机器约 2~5 秒。

## 一、游戏目标

4 位投资人（你 + 3 位 AI）在同一座城里行动，**20 回合**后总资产最高者成为"金融城之王"。

总资产 = 现金 + 公司估值 + 储蓄 + 持仓市值

公司估值会随**等级**提升而放大；已"爆雷"（doomed）的公司估值大幅缩水。

---

## 二、一回合的流程

```
掷骰（1~6 点） → 按方向逐格移动 → 落地结算 → 判定教学 → （可选）布陷阱 → 结束回合
```

每轮四位玩家依次行动，全部走完进入下一回合；每回合结束后会结算：

- **爆雷判定**：每家已持有的公司有概率爆雷，损失本金，公司转为无主
- **储蓄利息**：储蓄余额的 5%
- **持仓市值波动**：随机涨跌
- **差旅餐费**：每 2 回合扣除一次

## 三、棋盘与格子

棋盘是 **7×7 网格**，正中心的 3×3 是**杭州银行大楼**（单独建模的中央塔楼，不占格子），其余 **48 格**。

> 开局时棋盘布局会**随机打散**，但两处位置恒定：启动格与中心的杭州银行大楼。
> 你越有钱，杭州银行周围的楼就越密、越高。

| 类型 | 数量 | 落地效果 |
|---|---|---|
| `start` 启动格 | 1 | 停在格上领经营红利 |
| `center` 杭州银行 | 1 | 领取财富礼包 |
| `company` 公司 | 24 | 无主可收购；自己的可增资升级；他人的需付分红 |
| `save` 储蓄 | 7 | 判断后存入 |
| `stock` 股票 | 6 | 判断后建仓 |
| `rule` 监管 | 6 | 金融监管局合规问询 |
| `chance` 市场风向 | 1 | 随机抽取一张风向卡 |
| `risk` 风险 | 1 | 缴纳手续费 |
| `event` 事件 | 1 | 全城事件，所有投资人共同承担 |

**移动规则**：只能沿上下左右走，**不能走回头路**；若走进死胡同（四周全是走过的格子），则允许**原路返回**，保证剩余步数一定能走完。

## 四、公司：看资料，再掏钱

每家公司都有一份 **X-RAY 档案**：

| 字段 | 含义 | 字段 | 含义 |
|---|---|---|---|
| `g` | 营收增速 | `c` | 经营现金流 |
| `m` | 毛利率 | `f` | 风险提示 |
| `d` | 负债率 | `bld` | 建筑形态（决定外观与用途） |

另外还有**信用记录**（被执行 / 欠税 / 大股东质押 / 合同纠纷）与**市场口碑**（合作方评价 / 投诉量 / 舆情）两个维度。

查看资料后三选一：

| 动作 | 公司为真 | 公司为雷 |
|---|---|---|
| **投资** | 赚钱 | 亏钱，并标记为 doomed |
| **举报** | 误报罚 8 万 | 奖励 15 万，公司被监管查封 |
| **放弃** | 扣手续费 | 扣手续费 |

**增资升级**：已持有的公司可花钱升级，共 3 级，等级越高分红越高。
**分红**：踩到他人公司时支付 `租金 × (1 + 0.6 × (等级-1))`。
**风险陷阱**：在自己的公司布设陷阱，对手踩到会触发一次额外的防骗问答。

## 五、判定教学卡：每一题都有解法 ★

这是本版本最重要的升级。**无论你判对判错、投了放弃了举报了，每做完一次金融选择，游戏都会把这一题摊开讲：**

| 段落 | 内容 |
|---|---|
| ① **正确解法** | 这一题应该怎么选，一句话点明 |
| ② **决定性线索** | **代入这家公司的真实数据**（毛利率、增速、负债率、应收周转、质押比例…） |
| ③ **讲解 · 手册对照** | 引用手册原文 + 逐条列出命中的**红灯 / 黄灯 / 绿灯**具体条款 + 命中统计与评分 |
| ④ **下次怎么防** | 可迁移到下一家的动作清单 |
| ⑤ **你刚才的选择** | 按你实际选的投资 / 举报 / 放弃分叉复盘，并标出判定正误 |

### 覆盖范围

- **24 家公司全部有专属解法**：11 家问题公司（完整 5 段）+ 13 家绿灯公司（简版）
- **33 道反诈情景题**全部有规则对照（冒充公检法、刷单返利、非法荐股、虚假退费、养老诈骗、帮信罪、杀猪盘…）
- 题库中若出现未收录的题目，会自动用题目自带的风险提示生成一张最小教学卡，**保证任何一次判定都不会零反馈**

### 同类公司不撞车

11 家问题公司分属 6 类财务破绽（现金流背离 / 应收+商誉 / 存货积压 / 关联方占款 / 高负债质押 / 补贴依赖），但**每一家命中的红黄绿条款组合、决定性线索、评分与文案都不同**。例如同为"应收 + 商誉"型：

| 公司 | 决定性破绽 | 命中条款 | 评分 |
|---|---|---|---|
| 优品电商 | 应收周转 **265 天** | 现金流背离 + 毛利率异常 + 应收占比 + 周转异常 | 66 |
| 智通健康 | 商誉占总资产 **51%** | 商誉减值 + 现金流背离 + 毛利率异常 | 72 |
| 传媒万象 | 停滞 + 商誉 42% + 5 起诉讼 | 商誉减值 + 现金流背离 + 周转异常 + 信用瑕疵 | 84 |

为此扩充了手册清单：**红灯 7 → 10 条，黄灯 6 → 11 条**（新增条款在教学卡里标注「拟新增」，评审时可区分哪些是对原手册的扩展）。

### 三档模式下的不同表现

| 模式 | 教学卡行为 |
|---|---|
| 🧭 **引导模式** | **每次判定后强制弹出独立教学卡**（不计时，点「确定」继续） |
| 🎯 **普通模式** | 判定弹窗底部出现「**看解法**」按钮，想看才看 |
| 🔥 **困难模式** | **完全不提示**（专门用来检验学习成果） |

## 六、判断方法：手册五步

游戏内置一本《防骗手册》（按 `H` 随时打开，首次进入会自动展开），也是本作想教会你的东西：

| 步骤 | 口诀 | 要点 |
|---|---|---|
| 01 | **照毛利率** | 毛利率要跟同行比：高得离谱又讲不清为什么，就要警惕 |
| 02 | **验现金流** | 利润 ≠ 真钱。经营现金流要常年为正，并匹配净利润 |
| 03 | **查增长** | 增长要看从哪来：主营变强，还是靠赊账、借款、补贴堆出来 |
| 04 | **挑红黄绿** | 红灯一票否决、黄灯必须求证、绿灯三项齐备才放行 |
| 05 | **判结论** | 三项以上指标互相印证才下手；出现红灯就别自欺欺人 |

**评分规则**：每条红灯 +30 分、每条黄灯 +12 分，总分 ≥ 60 判为高危公司；命中任意一条红灯即一票否决。
**踩雷复盘**：在造假公司上投资会触发**五步推导链**，逐条对照你是从第几步开始失守的；终局还会做一次全局复盘。

## 十一、性能与首屏

考虑到路演现场可能用各种配置的机器，内置了自适应策略：

| 措施 | 效果 |
|---|---|
| **设备能力分级** | 按 CPU 核数 / 内存自动决定是否启用 2× 高清贴图、粒子数量、像素比上限 |
| **贴图分帧补做** | 48 张 512×512 贴图**绝不在首屏同步绘制**，让 loading 先消失、开始弹窗先出现，随后每帧 6ms 预算分帧补做 |
| **像素比上限** | 高配 2×，低配 1.25× |
| **运行期自适应** | 监测 FPS，低于 42 自动降像素比并关闭重特效（`html.lowfx`） |
| **贴图防泄漏** | 换贴图时释放旧纹理，长局不再累积显存 |
| **加载卡顿兜底** | 超过 7 秒自动浮现提示（硬件加速 / 换浏览器 / 本地打开），而不是让人干等 |

> **为什么强调"零网络请求"**：本作把 three.js、游戏逻辑、贴图生成全部内联进单个 HTML。
> 打开它**不访问任何服务器**，所以现场网络差不会导致游戏加载不出来——
> 如果感觉"卡"，那是本机解析 3D 引擎 + 建城的计算量，请开硬件加速或用本地文件打开。

### 专用测试版 `xray-demo-test.html`

为「现场演示时保证能看到判定教学卡」而派生，**正式逻辑与 `xray.html` 完全一致**，只额外做两件事：

| 差异 | 作用 |
|---|---|
| **公司向起点聚拢** | 24 家公司优先分配给距起点最近的格子（带少量随机抖动）。实测距起点最近的 5 家公司仅 1~2.2 格，3 步内有 9 家、4 步内有 15 家 —— 演示时前 1~3 步几乎必定踩到公司格 |
| **演示局也强制弹教学卡** | 原逻辑里 `demo` 模式只在判定弹窗塞「看解法」按钮、不自动弹卡，容易让人以为没有解法；测试版把 `demo` 也按 `guide` 处理，判定后自动弹卡 |

另含：顶栏「🧪 专用测试版」徽标、浏览器标题标注、启动时自动预选「演示局」。

> 正式演示请用 `xray.html`；调试教学卡、验证 24 家公司解法时用 `xray-demo-test.html`。

单文件内以 `/* ===== @ xray-xxx ===== */` 注释划分功能模块：

## 十四、修复记录

### 本轮新增

| 问题 | 原因 | 处理 |
|---|---|---|
| 判定后没有教学卡 | 钩子挂在了 `Ar()` 上，它要等玩家点「继续」才返回，此时弹窗已关 | 改挂真正的结算入口 `rd(i, n, t)`，在弹窗还开着时触发 |
| 教学卡内容为空 | 误把格子载荷当成题目对象取字段 | 题目取 `n.q`，公司定位改用载荷里的精确格索引 `t.tile` |
| **页面顶部常驻一行原始 JS** | `@ xray-demo-mode` 缺 `<script>` 开标签，代码当文本渲染 | 补回标签；同时让**演示局真正生效** |
| 天空飘着大块粉色方块 | 星尘着色器 `gl_PointSize ∝ 1/距离`，近景星点被撑爆 | 点径封顶 + 把过近星点推到半径 130 外 |
| 尘埃粒子是硬边方块 | `PointsMaterial` 没贴图 | 套用程序化生成的柔光圆点贴图 |
| 换贴图时显存累积 | 旧纹理未 `dispose` | 重绘时释放旧纹理 |
| 首屏在弱机上卡住 | 48 张 512 贴图在首屏同步绘制 | 改为分帧补做 + 低端机直接不升采样 |
| HUD 数字跳变 | 面板整块重绘 | 数字滚动过渡 |

### 既有关键修复

| 问题 | 原因 | 处理 |
|---|---|---|
| 同类公司扎堆 | 规划器按类型连续排布 | 开局随机打散，锚定启动格与杭州银行中心 |
| 部分公司无法收购 / 显示"他人持有" | 状态数组长度 24，棋盘 48 格 | 数组长度按棋盘实际格数 |
| 部分公司永不爆雷 | 爆雷检测只扫描前 24 格 | 扫描全部格子 |
| 步数未走完却卡住 | 禁止回头路导致死胡同无路可走 | 无新路口时允许原路返回 |
| 不知道该按哪个方向 | 提示只写死"按 W/A/S/D" | 提示实时列出当前可走方向 |
| 金额显示 `¥NaN万` | 分红计算读取越界的 `W.level` | 越界处加兜底并自愈 |
